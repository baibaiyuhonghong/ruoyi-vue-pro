## 2. 后端统一接口规范

### 2.1 返回结构

统一体 `cn.iocoder.yudao.framework.common.pojo.CommonResult`
（`yudao-framework/yudao-common/src/main/java/cn/iocoder/yudao/framework/common/pojo/CommonResult.java`）：

- 三字段 `code` / `msg` / `data`（`:27`、`:33`、`:37`），无 `success` 布尔字段。
- `success(data)`（`:72-78`）把 code 置 `GlobalErrorCodeConstants.SUCCESS`（0）、msg 置空串。
- `error(...)`（`:48-70`、`:117-119`）内 `Assert.notEquals(SUCCESS, code, "code 必须是错误的！")`，**禁止用 error 返回成功码**；`error(ErrorCode, params)` 会做 `{}` 占位替换。
- `isSuccess()` / `isError()` / `getCheckedData()` 标 `@JsonIgnore`（`:84`、`:89`、`:111`）不参与序列化；跨模块 API 调用用 `getCheckedData()` 拆包并在失败时抛 `ServiceException`。

**框架不自动包装返回值**：Controller 必须自己 `return success(...)`（静态导入）。`GlobalResponseBodyHandler` 的 `supports` 只匹配返回类型恰为 `CommonResult` 的方法，`beforeBodyWrite` 仅把结果写进 request attribute 供 `ApiAccessLogFilter` 记录，body 原样返回。

**HTTP 状态码恒为 200**：`GlobalExceptionHandler`（`yudao-spring-boot-starter-web/.../core/handler/GlobalExceptionHandler.java`）是 `@RestControllerAdvice`（`:56`），17 个 handler 全部返回 `CommonResult` 且无任何 `@ResponseStatus`（`:80-328`）。错误信息全在 body 的 `code` 里。Security 侧的未登录 / 无权限出口也一样：`AuthenticationEntryPointImpl` 写 code 401、`AccessDeniedHandlerImpl` 写 code 403，HTTP 仍是 200。

翻译规则：参数缺失/类型错/`@Valid` 失败/绑定失败/`ConstraintViolation`/请求体格式/文件过大/Content-Type 不支持 → **400**；404 → **404**；方法不匹配 → **405**；`AccessDeniedException` → **403**；`ServiceException` → 原样 code/msg；"表不存在" → **501** 并提示导入模块；其余兜底 → 记 `ApiErrorLog`（异步、含 traceId/参数/栈）后返回 **500**。

### 2.3 权限与登录注解


- `ss` = `YudaoSecurityAutoConfiguration.java:90-93` 的 `@Bean("ss")` → `SecurityFrameworkServiceImpl`（依赖 `PermissionCommonApi`）。方法还有 `hasAnyPermissions` / `hasRole` / `hasAnyRoles` / `hasScope` / `hasAnyScopes`。
- 方法级安全由 `YudaoWebSecurityConfigurerAdapter:48` 的 `@EnableMethodSecurity(securedEnabled = true)` 打开。
- 权限串三段固定：`模块:资源:动作`，动作集合 `query / create / update / delete / export / import`（生成器 `sql.vm` 固化）。
- 匿名接口用 `jakarta.annotation.security.PermitAll`（方法级或类级），启动时 `getPermitAllUrlsFromAnnotations`（`YudaoWebSecurityConfigurerAdapter:160-171`）扫描成 permitAll URL；追加白名单走配置 `yudao.security.permit-all_urls`（`yudao-server/src/main/resources/application.yaml:277-279`，目前只有 `/admin-api/mp/open/**`）。

### 2.5 分页机制

四段固定套路：

1. **请求 DTO**：`XxxPageReqVO extends PageParam`。`PageParam`（`yudao-common/.../pojo/PageParam.java:14-36`）：`pageNo` 默认 1 `@NotNull @Min(1)`；`pageSize` 默认 10 `@NotNull @Min(1) @Max(200)`；`PAGE_SIZE_NONE = -1` 表示不分页（导出用）。带排序用 `SortablePageParam`（加 `sortingFields`）。
2. **Controller**：`@GetMapping("/page")` + `@Operation` + `@PreAuthorize`，入参 `@Valid XxxPageReqVO`（**query 参数绑定，不是 `@RequestBody`**），返回 `CommonResult<PageResult<RespVO>>`；空列表短路 `new PageResult<>(total)`；导出复用同一 Service 方法并 `setPageSize(PAGE_SIZE_NONE)`。
3. **Mapper**：`default PageResult<DO> selectPage(reqVO)`，用 `LambdaQueryWrapperX` 的 `likeIfPresent` / `eqIfPresent` / `betweenIfPresent` / `inIfPresent`（值为空自动忽略条件）+ `orderByDesc`。
4. **框架层**：`BaseMapperX.selectPage(pageParam, wrapper)`（`:35-56`）→ `pageSize == -1` 走 `selectList` + `PageUtils.buildPageResult`；否则 `MyBatisUtils.buildPage` 造 MyBatis-Plus `Page` → `new PageResult<>(records, total)`。连表另有 `selectJoinPage`。

出参 `PageResult<T>` 只有 `list` + `total`，提供 `(list,total)` / `(total)` / `empty()` 构造。

真实三层样例（用户分页）：`UserController.getUserPage:103-117` → `AdminUserServiceImpl.getUserPage:340-352`（先按 roleId 取 id 集合，空则 `PageResult.empty()`）→ `AdminUserMapper.selectPage:28-37`。

### 3.2 命名习惯

- 表名 = `模块_业务` 两段式（`system_notice`、`infra_config`、`crm_customer`、`erp_stock_in`、`wms_shipment_order_detail`）；生成器据第一个 `_` 拆 `moduleName` / `businessName` / `className`，表注释去掉结尾"表"字作为 `classComment`（`CodegenBuilder.sanitizeComment:228-234`）。**所以表名必须两段式、表注释必须中文且以"表"结尾**。
- 主键列一律 `id`；DO 里 `@TableId` 可省略（`NoticeDO` 就没写）。
- 索引只有 `idx_` + 列名（`idx_create_time`、`idx_config_key`、`idx_user_id_user_type_read_status`）。**MySQL dump 里完全没有 `UNIQUE` 约束或 `uk_` 前缀** —— 唯一性一律由 Service 层 `validateXxxNameUnique` 抛错误码兜住。方言脚本改用 `CREATE INDEX idx_<表名>_<序号>` 并为每表建 `CREATE SEQUENCE <表名>_seq`。
- 列名小写下划线 ↔ Java 驼峰，靠 `map-underscore-to-camel-case: true`（`application.yaml:58`）。
- 状态/类型用 `tinyint`，取值写进 COMMENT（`状态（0正常 1停用）`、`公告类型（1通知 2公告）`）并与字典 type 绑定；布尔用 `bit(1)` → Java `Boolean`。
- 表级统一 `ENGINE = InnoDB AUTO_INCREMENT = n CHARACTER SET = utf8mb4 COLLATE = utf8mb4_unicode_ci COMMENT = '中文表名'`，每列还显式重复字符集；**无 `ROW_FORMAT`**。
- 特例：`AdminUserDO` 表名是 `system_users`（`AdminUserDO:22` 注释说明为规避 SQL Server 保留字 `system_user`）。

### 3.3 Java 映射

- `BaseDO`（`yudao-spring-boot-starter-mybatis/.../core/dataobject/BaseDO.java:22-64`）：`createTime`/`updateTime`/`creator`/`updater` 带 `@TableField(fill = INSERT / INSERT_UPDATE)`（creator/updater 显式 `jdbcType = VARCHAR`，注释说明用 String 是为将来非数值创建者留扩展），`deleted` 为 `Boolean` + `@TableLogic`；实现 `Serializable` 与 Easy-Trans 的 `TransPojo`；有 `clean()` 防前端传入审计字段被误写。

### 4.3 接口调用封装（三层）

1. **`vue3/src/config/axios/config.ts`**：`base_url = VITE_BASE_URL + VITE_API_URL`、`result_code: 200`、`request_timeout: 30000`、`default_headers: 'application/json'`。
2. **`vue3/src/config/axios/service.ts`**
   - 请求拦截（`:50-106`）：`Authorization: Bearer <token>`（白名单 `/login`、`/refresh-token` 不带）；租户开时注入 `tenant-id`，已登录且有访问租户时注入 `visit-tenant-id`；GET 加 `Cache-Control/Pragma: no-cache`；`x-www-form-urlencoded` 时 `qs.stringify`；参数序列化 `qs.stringify(params, { allowDots: true })`；`headers.isEncrypt` 时加密 body 并置 `X-Api-Encrypt: true`。
   - 响应拦截（`:109-239`）：按响应头解密；`blob`/`arraybuffer` 直传（但若导出返回的是 `application/json` 说明失败，转成 JSON 继续走错误分支）；`code === 401` → 无刷新令牌则登出，有则刷新 + **队列回放**并发请求（`:152-194`）；`500` → `errMsg500` 提示；`901` → 演示模式 HTML 提示；`code !== 0 && code !== 200` → `ElNotification.error({ title: msg })` 并 `Promise.reject('error')`；成功 `return data`（**整个信封**）。`ignoreMsgs`（"无效的刷新令牌"、"刷新令牌已过期"）静默 reject。
   - 登出 `handleAuthorized`（`:245-270`）：`resetRouter()` + `deleteUserCache()` + `removeToken()` + 刷新当前 URL 重走守卫。
3. **`vue3/src/config/axios/index.ts`**：对外 `request` 对象，`get/post/put/delete` 返回 `res.data`（即业务 payload），`download` 用 `responseType: 'blob'` 返回整个响应，`upload` 置 `multipart/form-data`，`postOriginal` 返回整个信封。

### 4.4 api 文件写法

### 5.3 照这条链复刻功能时会踩的坑（均有据）

1. **前后端字段不一致且无人校验**：`NoticeForm.vue:36-38` 有"备注"输入框并提交 `remark`，但 `NoticeSaveReqVO` / `NoticeDO` / 建表语句都没有 `remark` —— 该字段被静默丢弃。`formData` 未标 VO 类型，`ts:check` 也查不出来。新增字段必须四处同步：DDL → DO → SaveReqVO/RespVO → 前端 VO + 表单。
2. **租户写法在仓库内部并不统一**：`system_notice` 有 `tenant_id`，但 `NoticeDO extends BaseDO`（无 `tenantId` 字段）；`yudao.tenant.enable: true` 且 `ignore-tables:` 为空（`application.yaml:316-324`），租户条件靠 SQL 改写插件注入而非 DO 字段。照 `NoticeDO` 抄 `BaseDO` 会导致 Java 侧读不到租户号——需要读租户号时应继承 `TenantBaseDO`。
3. **必须同时补菜单 SQL 与角色授权**：页面菜单行（`component` + `component_name` 正确）与按钮权限行都要插 `system_menu` 并授予角色，否则前端菜单驱动的路由不存在（白屏/404），后端 `@PreAuthorize` 直接 403。生成器产出的 `sql/sql.sql` 就是干这件事的。
4. **唯一性不要指望数据库**：dump 里没有 UNIQUE 约束，重名只能靠 Service 层校验 + 错误码；漏写就是脏数据。
5. **审计字段不要自己写**：`creator/updater/createTime/updateTime/deleted` 由 `BaseDO` + `DefaultDBFieldHandler` + `@TableLogic` 接管，生成器也强制排除这些字段；手写会导致填充失效或逻辑删除被绕过。
